# musebot Web UI 规格(对齐微信桌面端)

> 状态:**已用 Vue 3 + Vite 重写完成**(`webui/`),界面与交互对齐旧 `web/`(零构建 `index.html` + `app.js`)。
> 旧 `web/index.html` 的样式已原样复用为 `webui/src/styles/app.css`;旧 `web/` 保留作对照与 dist 缺失时的回退。
> 服务端静态托管指向 `webui/dist`(`npm run web:build` 产物);dist 不存在时回退旧 `web/`。两套界面共享同一批 API 与既有行为。
> 演示:`MUSEBOT_DB=/tmp/mb-webui/m.db PORT=18860 npm run m1` + `npm run demo:seed`。
> 截图:`docs/webui-desktop.jpg`(聊天)、`docs/webui-delivery.jpg`(交付消息 + 文件)、`docs/webui-mobile.jpg`(移动端)。

> 参考:微信 macOS 客户端(3 栏)。目标不是"皮肤像",而是**行为像**:同一个动作在微信里怎么做,在这里就怎么做。
> 参考截图:`docs/ref-wechat.png`(用户提供的微信桌面端截图)。

## 0. 定位

musebot 是一个**多 bot 群聊客户端**。视觉语言直接采用微信:它有极强的一致性(单一绿色强调、方块头像、4px 圆角、没有投影的做法),而这套克制正好让"bot 工作卡"成为唯一的信息密度例外。

因此本项目的设计自由不花在"换一套配色/字体"上,而花在:**工作卡如何在不破坏微信语言的前提下,表达计划、派单、交付、文件**。

## 1. 骨架

```
┌────┬──────────────────┬──────────────────────────────────────────────┐
│ 56 │ 250              │ flex                                          │
│ 图 │ 搜索              │ 群名 · N 个成员            [🔍] [···]        │
│ 标 │ ───────────────  │ ─────────────────────────────────────────── │
│ 栏 │ 置顶群(绿色选中)  │            周五 22:00                        │
│    │ 群 2             │  ┌────┐  我拉个群可以吗                      │
│    │ 群 3             │  │ 头 │  ┌───────────────┐                  │
│    │ ───────────────  │  └────┘  └───────────────┘                  │
│    │ 群 4             │                              ┌──────────┐  │
│    │ 群 5             │                              │ 好的      │  │
│    │                  │                              └──────────┘  │
│    │                  │ ┌ 工作卡:计划 / 派单 / 交付(见 §5)          │
│    │                  │                                              │
│    │                  │ ─────────────────────────────────────────── │
│ ⚙  │                  │ 😊 📁 🗂 ✂ ˅                          [发送] │
└────┴──────────────────┴──────────────────────────────────────────────┘
```

- 三列固定宽度:rail `56px`,list `250px`,chat 自适应;整体最小宽 `900px`。
- ≤900px:list 变成抽屉(点群名左侧按钮或左滑),rail 保留。
- ≤560px:单栏,顶部返回按钮 + 群名,输入框贴底并避让安全区。

## 2. 设计 token

| 用途 | 值 |
|---|---|
| 应用底色 | `#F5F5F5`(聊天区)/ `#F7F7F7`(列表区)/ `#EDEDED`(rail) |
| 面板 | `#FFFFFF` |
| 分隔线 | `#E7E7E7`(列表行内)/ `#DCDCDC`(列之间) |
| 主文字 | `#191919`;次级 `#9A9A9A`;占位 `#B2B2B2` |
| 强调绿 | `#07C160`(按钮/发送/在线);选中行 `#2DC100` |
| 自己气泡 | `#95EC69`;他人气泡 `#FFFFFF` |
| 未读灰 | `#B1B1B1`(文字 `#FFF`);错误红 `#E05353` |
| 圆角 | 头像 `4px`;气泡 `4px`;卡片 `4px`;按钮 `4px`;搜索框 `4px` |
| 阴影 | 仅浮层(搜索下拉、菜单、新建群面板):`0 4px 16px rgba(0,0,0,.08)` |
| 字体 | `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`;数字/ID 用 `ui-monospace` |
| 字号 | 群名 13 / 消息 14 / 次级 12 / 时间 11 |
| 行高 | 消息 1.6;列表 1.35 |
| 间距 | 4 的倍数;消息区左右 20;气泡内 8×10 |

**禁止**:彩色左边框卡片、SaaS 式统一阴影卡片、渐变、玻璃拟态、超过 4px 的圆角、emoji 当图标(除工具栏允许的图形化图标)。

## 3. 左栏 rail(56px)

- 顶部:用户头像 `36×36`、圆角 4;未读总数红色徽标(左上角,`9+` 截断);头像本身是按钮,点开**个人资料**。
- 图标组:聊天(选中态用**实心**图标 + `#07C160`,未选中 `#5C5C5C` 描边 1.5px)和通讯录,24px;收藏/朋友圈没有真实内容,不放。
- 底部:手机(提示用手机访问同一端口)、设置(打开设置面板,默认停在「AI 模型」页)。
- 图标用**内联 SVG**,不要 emoji、不要图标库。

## 4. 群列表

- **群头像是成员拼图**:和微信一样,由群成员头像按 40px 方块拼成,最多 9 格,格与格之间 1px 白缝,整块 4px 圆角。
  - 成员 = 我 + roster(最多取 9 个),每格是「成员色块 + 姓氏/首字」,色相由 id hash 决定(和消息头像同色)。
  - 行数规则:`1→[1] 2→[2] 3→[1,2] 4→[2,2] 5→[2,3] 6→[3,3] 7→[1,3,3] 8→[2,3,3] 9→[3,3,3]`,每行横向居中。
  - 字号随格数降级:1 格 15px、2 格 11px、3–4 格 9.5px、5–9 格 6.5px(40px 里塞 3 列只剩 ~11px,再大就裁字)。
  - 单成员群用整块色(`.ag-single` 去掉内边距与缝隙),不显示白边。


- 顶部搜索:高度 28、圆角 4、底色 `#E9E9E9`(聚焦 `#FFF` + 1px 绿边框),placeholder「搜索」;左侧 12px 放大镜;`⌘K` / `/` 聚焦。
- 行:高度 64,左 12 头像 `40×40` 圆角 4(群 = 成员头像拼图),右侧两行:第一行 = 群名(13,粗)+ 时间(11,灰,右对齐);第二行 = 最后一条消息摘要(12,灰,单行省略)+ 未读徽标(右)。
- **置顶区**:顶部一条 `☰ N个置顶聊天` 行(11,灰,整行可点,右侧箭头折叠,状态存 `localStorage.mb.pins.collapsed`),下方才是置顶群;与普通区之间 8px 间隔。
- **我的 bot**:群列表下方是可折叠段(细分割线 + `☰ 我的 bot` + 数量 + 「+」新建 + 折叠箭头,状态存 `localStorage.mb.botsCollapsed`),每个 bot 一行(28px 头像 / 名字 / 能力 / 在群里),点行打开它的设置抽屉;不在本群时打开通讯录加入。这样不点任何按钮也能看到所有 bot,也能按需收起。
- 选中行:整行 `#2DC100`,文字与时间变白,摘要 `rgba(255,255,255,.8)`;hover(未选中)`: #EDEDED`。
- 摘要内容:真人消息显示文本;工作卡显示「[计划] 4 项」「[交付] report.md」这类短标签 + 文本。
- 未读:徽标 `16px` 圆角 4、`#B1B1B1` 底白字;`99+`。已读状态用 `localStorage: mb.read.<groupId>`(记录最后已读 entry id),切换群即写。
- 置顶:`localStorage: mb.pins`(群 id 数组);行右键菜单:置顶/取消置顶、标记已读。

## 5. 消息区

### 5.1 头部(52px)

- 居中:群名(14,600);右侧灰色小字「N 个成员」。
- 右侧图标:搜索(⌘F,打开消息内搜索条)、更多「···」(菜单:群公告、群置顶、清空本地已读、成员管理)。
- 点击群名:展开成员浮层(头像 + 名字 + 能力标签 + 忙碌小圆点)。

### 5.2 流

- 左右内边距 20,顶部 12,底部 16;`overflow-y:auto`,细滚动条(6px,`#C9C9C9`,hover 加深)。
- **时间分隔**:首条消息、跨天、或与上条间隔 >5 分钟时插入一行居中时间(11,`#B2B2B2`):当天显示 `HH:mm`,跨天显示 `昨天 HH:mm` / `周五 13:02` / `2025年11月3日 13:02`。
- 他人消息:左头像 `36×36` 圆角 4,头像右 8px 气泡;上边距 10;同人连续消息(<5min)不重复头像与名字,气泡上移 2px。
- 自己消息:右对齐,绿色气泡,头像在右。
- 气泡:白底 1px `#E5E5E5`;**无尾巴**;最大宽 `min(60ch, 520px)`;选中可复制;长文本自动换行,代码块用等宽 12px + `#F7F7F7` 底。
- 系统/事件行(中心灰字,12):「你邀请了 数据bot 加入群聊」「数据bot 已退出群聊」等。
- 工作卡(§5.4)独占一行,居中,最大宽 520。
- 新消息到达:若用户已在底部 → 平滑滚到底;**否则**显示底部悬浮「N 条新消息」按钮(点击滚到底并清未读)。
- 空态:居中灰字「还没有消息」+ 一行小字「发一句,或者派个需求」。

### 5.3 输入区

- 上边框 `#E0E0E0`,内边距 8×12。
- 工具条(上):**四个真按钮** —— 表情、文件、图片、语音(22px 描边图标,`#5C5C5C`,hover 变深)。没有「文件夹」——它和「文件」重复,已删。
  - **表情**:点开 24 个常用 emoji 的小面板,点哪个就插到光标处,并把草稿存进 `localStorage`。
  - **文件**:打开系统选文件框(可多选),`FileReader` 读成 base64 → `POST /api/groups/:id/uploads` → 群里出现一条 `chat.file`;气泡显示文件名+大小,点击下载。
  - **图片**:`accept="image/*"`,同样的上传通道;气泡里直接显示图片(最大 260×260),点击新窗口看原图。
  - **语音**:`getUserMedia` + `MediaRecorder` 真录音,录音条显示 `00:00` 计时和「取消」;再点一次麦克风结束并上传 `audio/webm`,气泡里是原生 `<audio controls>` 播放器。拿不到麦克风权限会明确提示,不假装录了。

- 输入框:textarea 无边框、透明底、最小 24 高、最大 120 高,滚动自适应;placeholder「输入消息」。
- 右侧:只有一个「发送」——纯文字按钮,有内容时 `#07C160` 文字 + 白底细边框,无内容时 `#B2B2B2` 文字;**不是**实心绿块(对齐微信)。
- **没有「派需求」按钮**:需求与闲聊走同一个输入框。后端 `chat()` 判"像不像请求"(动作+对象、或 `@领导`),像就交给领导分工,不像就是一句普通消息。
- 键盘:Enter 发送、Shift+Enter 换行、⌘Enter 也发送;输入法合成中不触发。
- 发送后:清空、保持焦点、滚动到底。
- 粘贴多行文本自动扩高;拖入文件 → 底部提示「文件发送暂未开放」。

### 5.4 工作事件就是消息(没有卡片)

微信群不会出现"带彩色标签的 HTML 卡片",所以这里也不出现。bot 之间靠 **@** 说话,人类插话照常:

| 事件 | 呈现 |
|---|---|
| `plan` | **领导发的一条消息**:「我拆成 4 件事,分给这几位:」+ 每行 `@数据bot 拉取并清洗Q3财务原始数据(需要 W1)` |
| `delivered` | **执行 bot 发的一条消息**:`@我 交付「拉取并清洗Q3财务原始数据」` + 正文前 240 字;**附件是文件气泡**(图标 + 文件名 + 大小,点击预览),不是卡片 |
| `started` | 居中灰字:`数据bot 开始处理「…」`,悬停有「取消」 |
| `blocked` | 居中灰字:`「…」在排队:没有空闲的 bot` |
| `failed` | 居中灰字(红):`「…」失败:依赖的任务失败` |
| `cancelled` | 居中灰字:`「…」已取消` |
| `assigned` / `done` | 不显示 |

- bot 消息与真人消息同一套气泡/头像/名字,只是作者是 bot;`@某某` 高亮成微信那种蓝(`#576B95`)。
- 正文里的 markdown(`**`、`#`、反引号、列表符)在气泡里压成纯文本;要原文点文件。
- 文件气泡:宽 ≤268、白底 1px 边、圆角 4、hover 微灰;长文件名省略号。
- 计划里的 `W1` 只在"需要 W1"这种依赖说明里出现,不做标题。

### 5.5 群信息 = 右侧边栏(不是弹窗)

点头部右侧「…」或头部群名,从**右侧滑出 320px 边栏**(`position: absolute; top:0; bottom:0`),覆盖聊天区右缘,聊天区不被挤压;左滑入 140ms。关掉:点边栏外的聊天区 / 再点「…」/ `Esc` / 右上小 `×`。手机(≤560)整屏铺满,像微信「聊天信息」页。

结构(从上到下):

| 区块 | 内容 | 行为 |
|---|---|---|
| 搜索群成员 | 灰底输入框 + 右上 `×` | 就地过滤下面的九宫格 |
| 成员九宫格 | 4 列,42px 圆角头像 + 11px 名字;末尾虚线「+」 | 点成员 → 小菜单「移出群聊」(领导/忙碌只提示原因);点「+」→ **添加成员弹窗**(见 §5.5b) |
| 群聊名称 | 名字 | 点开就地输入框 + 保存/取消 → `PUT /api/groups/:id` |
| 群公告 | 一行省略摘要,空则「未设置」 | 点开 textarea + 保存/取消 |
| 群置顶 | `N 条 · 每个 bot 都会读到` | 点开列表:每条「取消」,下面就是新增置顶输入 + 置顶/取消 |
| 我在本群的昵称 | 未设置 / 昵称 | 点开编辑,存 `localStorage.mb.nick`;**发消息时用它当作者名**(历史消息不改) |
| 备注 | 仅自己可见 | 点开编辑,存 `localStorage.mb.remark`;群列表和头部优先显示备注 |
| 查找聊天内容 | — | 关掉边栏并打开消息搜索框 |
| 消息免打扰 | 开关 | 存 `localStorage.mb.mute`;该群未读只显示灰点、不计入左栏角标 |
| 置顶聊天 | 开关 | 复用 `localStorage.mb.pins`(群列表置顶区) |
| 导出聊天记录 | — | 直接下载整群 markdown |
| 底部 | 清空本地已读记录 | 小字按钮,危险色 hover |

- 公告/置顶/名称/成员都是真写:服务端返回整份群详情 → 边栏原地重画;别的窗口开着同一群时,WS `{type:"detail"}` 也会让它跟着变。
- 领导不可移出(后端 409,界面只显示提示);正在跑任务的 bot 移出按钮会提示先取消。
- 刻意**不做**假项:群二维码这类没有对应能力的东西不摆出来。

### 5.5b 添加群成员 = 居中双栏弹窗

点九宫格末尾的「+」,出来的是微信那个"添加群成员"弹窗(不是内联展开):

```
┌────────────────────────┬──────────────────────────────┐
│ 搜索                    │ 添加群成员        已选择 1 个联系人 │
│ 可选成员  1 个可加入     │ ┌──┐ 设计bot              ✕  │
│ ● [设] 设计bot  design  │                              │
│ (灰底 #f5f5f5,可多选)   │ (白底,已选列表,✕ 取消勾选)     │
│                        │ ──────────────────────────── │
│                        │              [取消]  [添加]   │
└────────────────────────┴──────────────────────────────┘
```

- 左侧:搜索框 + 「可选成员 · N 个可加入」+ 行(`18px` 圆勾:选中变绿底白勾 / 未选空心)。**可多选**。
- 右侧:「已选择 N 个联系人」、已选列表(头像 + 名字 + 灰圆 `✕` 移除)、底部「取消」(灰) 「添加」(微信绿 `#07C160`,未选时禁用,选中数 >1 显示「添加(N)」)。
- 「添加」串行提交,失败逐个提示但不回滚已成功的;全成功后关弹窗 + 刷新详情,九宫格当场多出人。
- 弹窗尺寸 `min(1000px, 100vw-96px) × min(700px, 86vh)`;手机(≤560)改上下堆叠,列表 46% 高。
- 微信在这个弹窗底部还有「分享聊天内容」——我们没有转发能力,所以**不放**这个假入口。

### 5.6 文件气泡 = 能看、能下载

- 交付消息下面的文件气泡,点击打开浮层(**宽版 760px**,`max-height 82vh`,交付物常带表格,窄了读不了):顶部一行是大小 + 「原文」+「下载」,下面是正文。
- **`.md` 默认渲染,不是原文**:手写一个够用的 CommonMark 子集(标题、粗斜体、行内码、链接、代码块、表格、引用、有序/无序列表含一层缩进、分隔线),全部用 `textContent` 建 DOM —— 不拼 innerHTML,链接只放行 `http(s)/mailto///#`。
- 右上「原文」切到等宽源码,按钮变「预览」切回;渲染态与源码态共用同一份 `source`,来回切不重新请求。
- 文本类(`md/txt/json/csv/tsv/yml/diff/ts/js/py/html/css/sql/sh`)先拿 artifact 里的 preview 立刻占位,再用 `?inline=1` 把**归档文件全文**读上来重画 —— preview 有 20k 截断,归档没有。
- 非文本类只给下载,正文区一句话「该类型不支持在线预览,下载后查看。」
- 下载直连 `GET /api/groups/:id/files/:workId/<path>`,服务端带 `content-disposition`(ASCII 兜底 + `filename*=UTF-8''`),中文文件名不会乱码。
- 渲染样式仿微信文件预览:13px / 行高 1.75,`h1 16 · h2 15 · h3 14`,表格 12px 细边、表头浅灰,代码块 `#f7f7f8`,引用左 2px 竖线。

### 5.7 导出聊天记录

头部「…」→「导出聊天记录」:直接下载 `musebot-<群名>-<yyyymmdd-hhmm>.md`,里面是群名/导出时间/成员/群公告/群置顶 + 按日期分节的完整消息流(交付带正文和附件清单)。`?format=json` 是同一份内容的机器可读版,用来做归档。

### 5.5c 通讯录(左栏联系人图标)

点「通讯录」打开**左右两栏窗口**,照微信通讯录管理:左栏是搜索 + 「通讯录管理」+ 我的 bot 列表(每行头像、名字、能力,列表带数量),右栏是选中 bot 的资料(头像、名字、bot id、能力、所在群、来源、在群里),底部是「发消息 / 打开设置 / 加入本群」动作。它是 bot 地址簿,不是微信好友/朋友圈的模拟。

- 左栏点 bot 只切换右栏详情,不关窗;
- 搜索按名字/能力过滤;
- 开启「通讯录管理」后每行出现「设置」,直接打开 bot 设置;

### 5.8c IM 接入(通用 Webhook)

设置 → IM 接入,每个群一份:

- **入站 Webhook**:`POST /api/im/<groupId>/<token>`,body `{"sender":"张三","text":"帮我整理一版周报"}`。
- **Token**:只显示掩码(`imb_HAtu…xkBe`);「重新生成」后完整 token **只显示一次**,旧 token 立即失效(存 `musebot.im-bridge`)。
- **行为**:「启用这个桥」开关;入站走和输入框同一个 `router`:像需求就 `api.requirement`(群里出现「领导正在分工…」),闲聊就 `api.send` 落一条消息。
- **出站**:`GET /api/im/<groupId>/<token>/outbox?since=<lastId>`,按 id 升序返回 `id/kind/author/text|file/at`,最多 200 条 —— 给中转服务(企业微信机器人、公众号客服、脚本)主动拉。
- 最近入站用内存环形缓冲显示(只做诊断,不写群历史)。
- 明确边界:musebot 不直接连微信服务器(那需要企业主体、公网回调、验签),这里提供的是**标准化的中转接口**;任何能发 HTTP 的机器人都能接。

### 5.9a 新建 bot(+ 菜单)

列表右上角的 `+` 是一个两项菜单:**新建群** / **新建 bot**;「我的 bot」标题行的 `+` 则直接打开新建 bot 表单。
